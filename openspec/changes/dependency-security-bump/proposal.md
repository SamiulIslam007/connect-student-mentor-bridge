# Proposal: dependency-security-bump

## Why

`pnpm build` — one of the four gates in `AGENTS.md` §6 and a step of the `checks` job in `.github/workflows/ci.yml:54` — **fails on a cold tree today**: `CI=true pnpm build` exits `1` with `SecurityFatalError: Your version of Next.js is affected by a known security vulnerability`, and the same command exits `0` on the retry (observed 2026-11-21). `DEBT-71` records this as "stops once with a security nudge and needs a retry" and keeps nine moderate advisories open, seven of them on `next@16.4.3` — the framework that renders every page of the product.

## What Changes

- `apps/web/package.json:14` `next` moves from `16.4.3` to the latest patched `16.x` that clears the advisory set; no other runtime dependency moves.
- `esbuild@0.18.20` (reached through `drizzle-kit`) and `minimatch@10.2.6` (reached through ESLint) move **inside their parents' existing ranges only**; a bump that would need a parent major is not taken.
- `pnpm-lock.yaml` is regenerated by `pnpm install`, and the four gates plus **two consecutive cold builds** are the acceptance.
- No suppression: no environment variable or config is introduced to silence the security check.
- `DEBT-71` closes with the changelog notes for the two advisory areas this app actually touches (`use cache`, the image optimizer).

## Capabilities

### New Capabilities

None: no spec-level behaviour changes. The dependency tree changes; what the product does does not.

### Modified Capabilities

None. The repository's CI capability already requires that every check passes (`platform/ci-pipeline` → "Every pull request runs the full check suite"); this change makes the existing requirement true again rather than changing what it asks for.

## Impact

- **Code**: `apps/web/package.json` only for the runtime bump. No source file is expected to change; if the minor requires one, the change stops and reports instead of widening.
- **Dependencies**: `next`, plus `esbuild`/`minimatch` if their parents accept a patched version. Exact versions pinned, `pnpm-lock.yaml` committed.
- **Contract / data**: none. No migration, no API change.
- **Tests**: none added. The evidence is the gates themselves, `pnpm audit --audit-level=high`, and two cold `pnpm build` runs.
- **Docs**: `docs/known-debt.md` (`DEBT-71` closed with the advisories that remain, if any), `docs/decision-log.md` (D-234, D-235), `README.md` status line, `docs/milestones-and-phases.md` "Current state".

## Depends on

None. It is first because every later change is verified with the same gates.

## Out of scope

- **Any suppression of the security check** — an ignore flag, an env var, a forked build script. The check exists because the framework is affected; silencing it is the one thing this change must not do.
- **A React or Node major jump**, a TypeScript bump, a test-runner change, or a formatter/tooling refresh.
- **A dependency policy, a renovate/Dependabot configuration, or an automated bump lane.** One manual PR, read, verified.
- **Image and container scanning changes.** `trivy` already runs in `.github/workflows/ci.yml:79-91` and is untouched.
- **Any source change made necessary by the bump beyond a mechanical import or type adjustment** — that would be its own change.

## Risks and rollback

| Risk | Mitigation |
|---|---|
| The `next` minor changes rendering or build output | The web build emits the route table and 259 web tests run; a visual sanity check of one page is a task, not an assumption |
| A patch bump pulls a transitive dependency that the image scan flags | The image job (`trivy`, HIGH/CRITICAL, `exit-code: 1`) runs on the PR; a new finding stops the change |
| `esbuild`/`minimatch` can only move with a parent major | Then they stay and `DEBT-71` closes with a dated row naming the parent, the advisory and the trigger for the major |
| The nudge fires on a runner the first time, so PR CI fails while local retries pass | The acceptance runs the build twice on a clean `.next`, and the PR records both exit codes |

**Rollback**: revert the single commit; `pnpm-lock.yaml` returns with it, and no data or schema is involved.

**Traces to** `DEBT-71`, `SEC-SUP-2`, `SEC-SUP-4`, `platform/ci-pipeline`, D-234, D-235.
